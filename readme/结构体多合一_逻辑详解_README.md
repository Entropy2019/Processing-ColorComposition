# `#04#结构体多合一.py` 功能逻辑详解（侧重交互逻辑与规则）

> 说明：当前仓库中对应实现是 Processing 草图代码（文件名：`利用Processing绘制方块的单点透视图`），本 README 按你关注的“功能逻辑”维度来拆解，视觉部分仅做必要说明。

---

## 1. 功能总览（先看这个再看细节）

该程序本质是一个**透视立方体生成器**，通过一套“结构体 + 规则”驱动流程，完成从“空间点定义”到“投影、筛面、着色、批量绘制”的全过程。

核心能力可以理解为 5 个模块：

1. **结构定义层**：`Pos2`、`Pos3` 两个结构体（类）用于组织坐标数据。  
2. **规则层**：包括透视规则、尺寸范围规则、深度位移规则、颜色规则。  
3. **筛选层（可见面选择）**：根据投影后中心点象限决定绘制哪两个侧面（避免“全部都画”的混乱）。  
4. **批量生成层**：按网格扫描生成大量立方体，形成“空间阵列”效果。  
5. **输出层（导出）**：当前版本是一次性渲染到画布，通常由 Processing 自带保存机制导出图片。

## 2. 结构体如何组织“结构树”（你关心的“如何读取结构数”）

虽然代码不是显式树结构，但逻辑上是一个很清晰的“数据树”：

- **根节点：全局参数**  
  `Len / mid / sd / Cube_len / Z / max_move_z / max_cube_len / min_cube_len`  
  这些参数决定画布尺度、网格尺度、透视强度、随机范围。

- **中间节点：坐标结构体**  
  - `Pos3`：世界坐标（x,y,z）
  - `Pos2`：投影坐标（x,z）

- **叶节点：单个立方体实例**  
  每个立方体由 `P1 ~ P44` 等 8 个顶点（+中心点 P0）组成，再映射到 `p1 ~ p44` 进行 2D 绘制。

### 2.1 `Pos2`（二维投影坐标）

职责：承接透视计算结果，供 `quad(...)` 直接绘图。  
特点：

- 只有 `x,z` 两个分量（这里用 `z` 作为屏幕纵向）。
- 支持 `int` 和 `float` 构造，最终都转为整型，便于像素绘制。

### 2.2 `Pos3`（三维空间坐标）

职责：保存空间点，并提供 `perspective()` 投影函数。  
核心：

```text
x' = x * sd / (sd + y)
z' = -z * sd / (sd + y)
```

解释：

- `y` 越大，分母越大，投影坐标越小 → 远处收缩（透视感）。
- `z` 带负号，做了坐标系方向映射（让画面方向符合预期）。

### 2.3 如何“读取结构”

可按以下顺序理解（非常实用）：

1. 先读取全局常量（决定世界边界和随机上下限）。
2. 读取 `Pos3.perspective()`（理解所有 3D→2D 的统一入口）。
3. 读取 `drawcube(...)`（理解单体几何构造与筛面规则）。
4. 读取 `drawrandomcube(...)`（理解随机变化规则）。
5. 读取 `drawcubearray()`（理解批量分发规则）。

## 3. 创建规则（重点：怎么“生成”）

## 3.1 全局网格与尺度规则

- `Len=1080`：画布基准长度。
- `num=10` → `Cube_len=Len/num`：基础立方体网格边长。
- `Z=Cube_len*5`：把阵列分到前后两个层面（`z=-Z` 和 `z=+Z`）。

这意味着：程序不是随机散点，而是先有**规则化网格骨架**，再在骨架上做随机扰动。

## 3.2 单体几何构造规则

`drawcube(P1, cube_len)` 中：

- `P1` 作为一个角点起始。
- 按 `cube_len` 推导出其余 7 个顶点（`P2, P3, ... P44`）。
- 再为每个 3D 顶点求 2D 投影 `p1, p2, ...`。

你可以把这看成“参数化立方体模板”：

- 输入：起点 + 尺寸
- 输出：可绘制的 6 面中的若干面

## 3.3 随机变形规则

`drawrandomcube(P1)` 中有两类变化：

1. **深度偏移**：
   - 先取 `n=random(0.5,1.25)`
   - `move_z=n*n*max_move_z`（平方放大高值概率影响）
   - 随机正负号（前后浮动）

2. **尺寸扰动**：
   - 边长在 `[min_cube_len, max_cube_len]` 随机

结果：同网格位置会出现大小和深度不同的立方体，形成有层次但不杂乱的纹理。

## 4. 筛选规则（重点：如何“筛选可见面”）

你提到的“如何筛选”，在这份代码里对应**可见面逻辑筛选**。

程序先画正面（front），然后根据中心点 `p0` 所在象限，选择另外两个面：

- `p0.x < 0 && p0.z < 0`：画右面 + 底面
- `p0.z < 0`：画左面 + 底面
- `p0.x < 0`：画顶面 + 右面
- 否则：画顶面 + 左面

这套规则的价值：

1. 避免 6 面全画导致前后关系冲突。
2. 保持“近似正确”的观察方向一致性。
3. 通过象限判断简化复杂遮挡计算（高效）。

如果你要扩展“筛选器”，可以在这里增加：

- 按尺寸筛选（仅画大于阈值的立方体）
- 按深度筛选（仅画前景或背景）
- 按随机种子稳定筛选（复现实验图）

## 5. 功能交互流程（逻辑交互，不是 UI 按钮）

当前版本是“代码驱动式交互”，交互路径是：

1. **参数输入阶段**：通过修改常量（如 `num`、`max_move_z`）定义生成策略。
2. **批量分发阶段**：`drawcubearray()` 遍历网格，逐点调用 `drawrandomcube()`。
3. **单体决策阶段**：`drawrandomcube()` 决定当前立方体的尺寸与深度扰动。
4. **可见面筛选阶段**：`drawcube()` 通过象限规则决定绘制面。
5. **着色决策阶段**：每个面调用 `fill_xxx()` 随机二选一配色。
6. **输出完成阶段**：`setup()` 一次性渲染结束。

这是一种非常典型的“规则系统流水线”：

`参数规则 -> 数据实例化 -> 过滤决策 -> 渲染输出`

## 6. 导出逻辑（如何导出）

当前代码本体没有显式 `save()` 调用，但在 Processing 中通常有三种导出策略：

1. **手动导出**：运行后在 IDE 中保存画布。  
2. **代码导出（推荐）**：在 `setup()` 末尾增加：
   ```java
   saveFrame("output/cube-####.png");
   ```
3. **批量导出**：改为在 `draw()` 循环生成多帧并 `saveFrame()`。

如果你要“功能化导出”，建议加三个参数：

- 导出目录（如 `output/`）
- 文件前缀（如 `composition`）
- 时间戳或随机种子（便于回溯）

## 8. 一句话总结

这份程序最关键的不是“画方块”，而是：

- 通过 `Pos3 -> Pos2` 的透视映射建立空间秩序；
- 通过象限筛面规则建立可见性秩序；
- 通过网格+随机扰动建立复杂而可控的生成秩序。
